# Как выпустить версию

Клиент сам проверяет, не появилось ли версии новее, и показывает полоску внизу
списка чатов. Полоска качает apk с гитхаба и отдаёт его системе на установку.

Порядок при выпуске такой, и порядок здесь важен.

1. Поднять номер в клиенте: `MargeletConfig.APP_VERSION`, и рядом
   `APP_VERSION_CODE` в `gradle.properties`. **Оба живут в клоне телеги, а не
   в этом репозитории** — значит, после правки надо скопировать
   `MargeletConfig.java` обратно в `java/margelet/` и перегенерировать патч.
   Забыть это легко и незаметно: выпуск уйдёт правильным, потому что собирают
   из клона, а в репозитории номер останется прошлым. Так и случилось на
   0.99.28 — apk вышел с 0.99.28, а в гите до сих пор стояло 0.99.27, и
   следующая сборка из репозитория ушла бы с чужим номером.
2. Собрать apk.
3. Положить apk в ветку `apk` — и под своим номером, и как `margelet.apk`.
4. Только теперь поднять номер в [version.json](../version.json) — **и вместе
   с ним адрес `apk`, на файл с этим номером**.

Последним шагом именно `version.json`, потому что он и есть объявление: как
только в нём появился номер больше, у всех всплывает полоска. Если объявить
раньше, чем apk лежит на месте, люди нажмут и получат ошибку.

## version.json

```json
{
  "version": "0.2",
  "apk": "https://github.com/narezany/margelet/raw/apk/margelet.apk",
  "about": "What changed.",
  "about_ru": "Что изменилось."
}
```

| | |
|---|---|
| `version` | номер последней версии. Сравнивается числами через точку, поэтому `0.10` больше `0.9` |
| `apk` | откуда качать. **Ссылка с номером версии, а не `margelet.apk`** — см. ниже |
| `about` | что нового, одной строкой. `_ru` и `_zh` — переводы |

## Почему ссылка с номером, а не постоянная

Сначала здесь стояло `margelet.apk` — один адрес на все времена. Так было
короче, и так было неправильно.

Гитхаб отдаёт файлы из ветки через кэш, `max-age=300`. Имя постоянное, значит
первые пять минут после выпуска по этому адресу можно получить байты **прошлой**
сборки — молча, с кодом 200. Обновлялка их скачивала, ставила, приложение
оставалось старым, полоска появлялась снова — и так по кругу, без конца.
Владелец на это наступил на 1.0.14: обновлялся через саму Margy и раз за разом
получал 1.0.13.

Адрес с номером версии кэш видит впервые, поэтому отдаёт настоящий файл. Это
единственная причина, и она стоит лишней строчки при выпуске.

Забыть поменять `apk` вместе с `version` — ошибка того же рода, что забыть
первый шаг: люди будут скачивать прошлую сборку и не понимать, почему
обновление не кончается.

`margelet.apk` в ветке остаётся: на него ссылаются README и люди, качающие
руками. Обновлялка им больше не пользуется.

## Чего оно не делает

Само ничего не ставит и не качает: скачивание начинается по нажатию, а ставит
apk система, спросив человека. Молча подменить себе приложение нельзя, и это
правильно.

Недокачанный файл не считается готовым. Оборвалась сеть или нажали отмену —
кусок удаляется, и полоска снова предлагает скачать, а не «установить» то,
чего нет.

Забыть первый шаг — самая дорогая ошибка: сборка со старым `APP_VERSION`
будет всю жизнь предлагать обновиться сама на себя.

## Как часто клиент спрашивает

По умолчанию раз в три минуты; человек меняет это в настройках форка, от трёх
минут до суток, и может выключить совсем. Кнопка «Проверить сейчас» там же
работает всегда, даже когда автоматические проверки выключены.
